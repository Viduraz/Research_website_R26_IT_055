AIMS · Project R26_IT_055

Skeleton-Based Person Identification & Biometric Gait Analysis

Himaya Jayasinghe’s component uses 3D skeletal body proportions and walking patterns to identify enrolled people, including when facial visibility is poor.

Himaya Jayasinghe · Team Member
Student ID: IT22240392 · Component Owner
Component overview · privacy-aware identity

Identify people through body geometry and gait

The service extracts a 3D pose from webcam or IP-camera frames, checks keypoint quality, and builds two complementary identity representations: relatively stable body proportions and movement patterns over time. This can provide an identity cue when a face is occluded or turned away.

The documented design includes open-set rejection so uncertain matches can remain unknown instead of being forced into an enrolled identity.

Component pipeline
Camera frame→3D pose landmarks→Body & gait features→Identity fusion→Match / reject

This page describes the implementation details supplied for this component.

Feature design

Static proportions and temporal movement

29D

Anthropometric profile

A 29-dimensional world-coordinate feature vector describes normalized segment lengths, body-proportion ratios and selected metric body dimensions. Trunk-based normalization is used to reduce camera-distance effects.

15D

Gait kinematics

A sliding 30-frame window describes joint angular velocities, gait-cycle frequencies and amplitudes, symmetry and lateral body sway. Knee-angle variation filters out stationary pose jitter.

30×8

Sequence representation

A temporal matrix of normalized joint angles is supplied to the bidirectional LSTM gait classifier.

Model and decision path

Combine evidence and reject uncertain identities

Complementary matchers

The documented system combines a biometric prototype matcher using regularized Mahalanobis distance, an RBF SVM for static features and a deep bidirectional LSTM for gait sequences.

Fusion and stranger handling

A rule-based fusion layer weighs static and temporal identity scores and applies confidence and ambiguity checks. An open-set threshold allows a person to be rejected as unknown.

Reported identification results

The component specification reports 94.2% field identification accuracy and 91.8% identification accuracy when faces are occluded. The evaluation protocol and test population were not supplied with this website brief; see Results for interpretation.

Integration

Streams and services

The supplied architecture describes a React client and FastAPI service, with webcam frames sent through /ws/stream and IP-camera streaming through /ws/ip-stream. MongoDB stores identity and biometric records.

Responsible use

Identity is an estimate

Pose quality, camera angle, clothing, mobility differences and the enrolled sample set can affect matching. Low-quality or ambiguous frames should not be treated as a confirmed identity.
